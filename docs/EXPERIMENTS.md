# 실험 계획과 기록

## 가설
작업 증가 시 병렬화가 전체 완료 시간을 줄이는지, 시작·대기·저장 비용이 이득을 상쇄하는 구간이 있는지 검증한다.
로컬 성능을 AWS 성능으로 표시하지 않는다. 예측 정확도 향상을 클라우드 효과로 해석하지 않는다.

## 통제
동일 데이터 버전, 코드·컨테이너 digest, seed, 입력 작업 목록, 작업자별 1vCPU/2GB, 수치 라이브러리 스레드 1.
동시 실행 목표 1·2·4. 작업 10·100·1000 후보. 동일 manifest를 반복 사용.
예비 실험에서 작업 묶음 크기를 정하고 본 실험 도중 변경하지 않는다.
조건별 반복 3회. 예산 때문에 축소 시 실제 조건을 보고서에 기재한다.

## 로컬
python -m lab.benchmark examples/manifest.json --workers 1 2 4 --repeats 3
예시 dataset_id를 실제 로컬 버전으로 교체한다.
동일 입력별 metrics/curve를 비교하고 불일치 시 실험 실패. 기록은 data/benchmarks.

## AWS
infra/README.md의 스택·이미지 준비 후 python -m lab.cloud experiment를 명시적으로 실행한다.
각 작업의 Batch createdAt/startedAt/stoppedAt과 내부 계산 시작·종료를 저장.
클라이언트 전체 시간에는 S3 결과 수신도 포함되므로 보고서에서 경계를 명시한다.
관측 동시성은 내부 계산 구간 중첩이며 Fargate 자원 할당 시간과 동일하지 않다.
AWS 결과의 동등성은 비교 전 null이며 검증되지 않은 상태를 true로 표시하지 않는다.

## 비용
작업당 비용=(해당 실행의 계산 사용료)/완료 작업 수.
Fargate 청구 시간은 내부 Python 계산 시간과 다르다. 현재 프로그램은 비용 값을 null로 기록하며 임의 단가를 사용하지 않는다.
이미지 다운로드·최소 청구 단위·S3·ECR·CloudWatch·CloudFront 및 세금을 별도로 반영한다.
ap-northeast-2의 실험일 단가와 실제 청구 자료를 보관한 뒤 산정한다.
목표 월 3만 원. 알림은 강제 차단이 아니다. 예비 작업 1개부터 시작, timeout 기본 600초·최대 1800초, max vCPU 4.
상시 서버 비용과 비교하는 값은 실측 절감액이 아니라 동일 관찰 기간의 비용 모델로 명시한다.

### 사전 비용 모델 (2026-09-27, 실측 전 추정)
AWS 실행 전에 예산 범위를 확인하기 위한 추정이다. 실제 실험 후 Batch 작업 시각과 청구 내역으로 다시 산정하며, 이 값을 실측 비용으로 보고하지 않는다.

**단가** — AWS Price List API, ap-northeast-2 On-Demand, Linux/x86

| 항목 | 단가 | 가격표 게시일 |
|---|---|---|
| Fargate vCPU | $0.04656 / vCPU·시간 | 2026-09-11 |
| Fargate 메모리 | $0.00511 / GB·시간 | 2026-09-11 |
| 공인 IPv4 (작업 실행 중) | $0.005 / 시간 | 2026-09-17 |
| ECR 이미지 저장 | $0.10 / GB·월 | 2026-09-11 |
| CloudWatch Logs 수집·저장 | $0.76 / GB, $0.0314 / GB·월 | 2026-09-22 |
| S3 Standard 저장·요청 | $0.025 / GB·월, PUT $0.0045 / 1천 건, GET $0.0035 / 1만 건 | 2026-09-26 |

환율 1 USD = 1,362.6원(토스증권 Open API 환율 조회, 2026-09-27 01:06 KST). 한국 결제 주소는 부가세 10%가 별도로 붙는다.

**가정**
- 작업자 1개 = 1 vCPU·2GB(`infra/cloudformation.json`). 시간당 $0.04656 + 2 × $0.00511 + IPv4 $0.005 = **$0.06178(약 84원)**.
- 백테스트 1건 계산 0.1초. 로컬 실측 평균은 0.033초(11개 전략 × 4종목, 44건, 수치 라이브러리 1스레드)이며, 클라우드 vCPU 속도 차이를 3배 여유로 둔다.
- 작업마다 준비 시간 40초(이미지 받기, 파이썬 시작, S3 입출력). Fargate는 초 단위, 작업당 최소 1분 과금.
- 작업별 청구 시간 = max(60초, 40초 + 작업자당 백테스트 수 × 0.1초).

**시나리오**

| 시나리오 | 청구 시간 | 비용(부가세 전) | 부가세 포함 |
|---|---|---|---|
| 본 실험: 작업 10·100·1000개 × 작업자 1·2·4 × 반복 3회 (Fargate 작업 63개) | 71분 | $0.073 ≈ 100원 | 약 110원 |
| 확대 예시: 2,715종목 × 11전략 ≈ 29,865건, 작업자 4 | 52분 | $0.054 ≈ 74원 | 약 81원 |
| 월 고정비: ECR 이미지 ≤0.5GB, S3·로그·요청 | — | ≤ $0.05 ≈ 70원 | 약 75원 |

- 본 실험의 작업 수가 10·100개인 조건은 계산이 수 초라 모든 작업이 최소 1분으로 청구된다. 작은 작업에서는 준비 시간과 최소 과금이 계산 시간보다 크다는 것이 가설("시작·대기 비용이 병렬 이득을 상쇄하는 구간")과 직접 연결된다.
- CloudFront는 월 1TB 전송·1천만 요청까지 무료 구간이고, AWS Batch 자체와 이 템플릿의 예산 알림 1개는 추가 요금이 없다. 작업이 없을 때 Fargate 연산·공인 IP 요금은 0이다.
- 확대 예시의 병목은 요금이 아니라 토스 일봉 수집 시간(종목당 약 5초, 수 시간)이다.

**상시 서버와의 비교 (동일 한 달 비용 모델)**

| 방식 | 한 달 비용(부가세 전) |
|---|---|
| Fargate 배치: 본 실험 1세트 + 고정비 | 약 170원 |
| 상시 서버 0.5 vCPU·1GB × 730시간 + 공인 IP | $24.37 ≈ 약 3.3만 원 |
| 상시 서버 1 vCPU·2GB × 730시간 + 공인 IP | $45.10 ≈ 약 6.1만 원 |

같은 계산을 상시 서버로 한 달 운영하면 배치 방식보다 약 200~360배 비싸며, 월 목표 3만 원을 넘는다. 이는 청구서 기반 절감액이 아니라 공식 단가로 만든 비용 모델이다.

**비용을 키우는 요인**
- NAT 게이트웨이: 상시 과금이므로 템플릿에서 쓰지 않는다(public subnet + 공인 IP).
- 멈춘 작업: 작업 제한 시간 기본 600초, 최대 vCPU 4로 최악의 경우도 제한된다.
- 로그 과다 출력, 사용하지 않는 ECR 이미지·S3 버킷 방치.
- 예산 알림(기본 월 15달러)은 알림일 뿐 자동 차단이 아니다.

**실측 후 산정 방법**
작업별 청구 초 = Batch `stoppedAt − startedAt`(최소 60초)로 계산해 위 단가를 곱하고, 같은 기간의 Cost Explorer·청구서(서비스별 Fargate·VPC IPv4·ECR·CloudWatch·S3)와 대조한다. 결과 JSON의 `estimated_compute_cost`는 이 대조가 끝난 뒤에만 채운다.

## 장애와 통계
실패한 실험은 성공 시간 통계에서 제외하되 실패 수를 별도 보고. 실패 결과도 삭제하지 않는다.
취소 후 잔여 AWS 작업 확인. 수집 및 실행 시각, 이미지 버전, 로그를 보관한다.
완료 시간 평균·최솟값·최댓값, 관측 동시성, 처리량과 비용을 제시한다.

AWS 비교: python -m lab.report compare data/benchmarks/A.json data/benchmarks/B.json
CSV 요약: python -m lab.report csv data/benchmarks/A.json --output summary.csv
